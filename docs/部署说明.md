# 部署说明 · 飞牛 fnOS + Docker Compose

一套仓库跑起「家庭 NAS 一体化平台」：1 个门户 + 6 个业务应用 + 1 个定时任务进程，外加 PostgreSQL。
各应用各自监听独立端口（3210-3216），**由外部反向代理（本方案用 Lucky）按子域名分发**，
本仓库不再内置 nginx 网关。

---

## 一、整体结构

| 容器 | 作用 | 容器内端口 | 宿主机端口 | 反代子域名（示例） |
|---|---|---|---|---|
| `portal` | 门户：登录入口 + 各平台卡片 + 后台管理 | 3000 | 3210 | `nav.<root>` |
| `bill` | 家庭记账 | 3000 | 3211 | `cash.<root>` |
| `anniversary` | 纪念日（农历/公历倒计时） | 3000 | 3212 | `anniversary.<root>` |
| `work` | 工作台 | 3000 | 3213 | `work.<root>` |
| `pregnancy` | 孕期待办 | 3000 | 3214 | `pregnancy.<root>` |
| `travel` | 旅行足迹 | 3000 | 3215 | `travel.<root>` |
| `todo` | 待办清单 | 3000 | 3216 | `todo.<root>` |
| `worker` | 定时任务（提醒扫描、派发、重试） | — | 不映射 | — |
| `migrator` | 一次性：跑迁移 + 种子，跑完退出 | — | 不映射 | — |
| `postgres` | PostgreSQL 16 | 5432 | 不映射 | — |

- **入口 = Lucky**：在 Lucky 上按子域名把请求转发到对应的 `NAS_IP:321x`
  （例如 `cash.<root>` → `192.168.1.10:3211`）。
- **单点登录（SSO）**：登录态是 cookie 作用域 `.<root>` 的 JWT，在门户登录一次，
  其余子域免登录。**这依赖各子域名都指向同一台 NAS**（无论经 Lucky 还是直连）。

---

## 二、前置条件

1. 飞牛 fnOS 已安装并开启 **Docker**（应用中心里叫「Docker」）。
2. 开启 **SSH**（设置 → 远程访问 → SSH），用电脑 SSH 进 NAS，方便敲 compose 命令。
   也可以在飞牛的 Docker 应用里用图形界面操作，但命令行更顺手。
3. 确认 `docker` 与 `docker compose`（v2）可用：

```bash
docker version
docker compose version      # 需要 v2，认准 "Docker Compose version v2.x"
```

> 容器依赖 `depends_on.condition: service_completed_successfully`，
> 这是 Compose v2 的特性，v1（`docker-compose`）不支持。

## 三、拿到代码并配置环境变量

### 1. 放置代码

选一个放在你的存储卷上的目录，例如 `/vol1/1000/nas-platform`：

```bash
cd /vol1/1000
git clone <仓库地址> nas-platform
cd nas-platform
```

（不想用 git 的话，把整个目录打包上传、解压到同一层级即可。）

### 2. 生成并填写 `.env`

`.env` 放在**仓库根目录**，`docker compose` 会自动读取。它已被 `.gitignore`/`.dockerignore`
排除，不会进仓库也不会进镜像。

```bash
cp .env.example .env
```

用编辑器打开 `.env`，**至少**改这几项：

| 变量 | 说明 |
|---|---|
| `PG_PASSWORD` | 数据库密码，自己设一个强的 |
| `AUTH_SECRET` | 会话密钥，**七个应用必须一致**。生成：`openssl rand -base64 32` |
| `SERVICE_TOKEN` | 应用间内部接口令牌。生成：`openssl rand -hex 24` |
| `CRON_SECRET` | 定时任务手动触发密钥。生成：`openssl rand -hex 24` |
| `ADMIN_PASSWORD` | 初始管理员密码，**首次启动后立刻登录改掉** |
| `PG_DATA_DIR` | 数据库数据目录（宿主机路径），如 `/vol1/1000/nas-platform/pgdata`；见第三节第 3 步 |
| `NAS_ROOT_DOMAIN` | 你的根域，例如 `example.com`（**不带协议和端口**） |
| `NAS_PUBLIC_PROTO` | 内网 http 就填 `http`；走了 https 再改 `https` |
| `NAS_PUBLIC_PORT` | 外部反代对外的端口，**要连冒号一起填**（如 `:1443`）；走 80/443 留空 |
| `PORTAL_SUBDOMAIN` 等 | 各应用子域前缀，默认 `nav`/`cash`/`todo`/`anniversary`/`work`/`pregnancy`/`travel`；想改就填，例如 `ANNIVERSARY_SUBDOMAIN=birthday` |
| `AUTH_COOKIE_SECURE` | 内网 http 必须 `false`，否则浏览器不回传 cookie |

其余（图床、企业微信、SMTP、高德地图）按需填，留空不影响启动。
各应用地址（`PORTAL_URL` 等）**全部留空即可**，会按 `NAS_ROOT_DOMAIN` 自动拼出来。

### 3. 准备挂载目录（数据库 + 照片）

```bash
# 数据库数据目录（对应 .env 的 PG_DATA_DIR）。属主必须是镜像里的 postgres 用户：
# postgres:16-alpine 的 uid 是 70，权限不对容器会起不来。
mkdir -p /vol1/1000/nas-platform/pgdata
chown -R 70:70 /vol1/1000/nas-platform/pgdata

# 账单票据（读写）+ 旅行相册（只读）
mkdir -p /vol1/1000/photos
# 待办本地图片（没配图床时才用）
mkdir -p /vol1/1000/photos/todo
```

> 容器内进程以 uid `1001`（`nextjs`）运行。若上传报权限错误，
> 给目录放宽权限：`chmod -R 775 /vol1/1000/photos`（或让属主包含该 uid）。

## 四、子域名解析（SSO 的关键）

把 `*.example.com` 指到 NAS 的内网 IP，任选一种：

1. **内网 DNS 泛解析**（推荐）：在路由器 / AdGuard Home / dnsmasq 上给
   `*.example.com` 加一条 A 记录指向 NAS，例如 `192.168.1.10`。
2. **hosts 文件**：只在单台电脑上用，手动加 `nav.example.com` 等各条。
3. **Tailscale MagicDNS + split DNS**：外网访问时用，见第九节。

> 解析不通时，浏览器根本不会带 cookie，表现为**「门户登录成功、跳到账单又掉线」**。
> 这是最常见的坑，先确认 `ping nav.example.com` 能通。

只用 IP 直连、不配域名也能用：把所有应用地址看成 `http://<NAS_IP>:321x`，
但要用根域 `AUTH_COOKIE_DOMAIN` 留空、且各应用地址要手工填成 IP:端口。
SSO 只在**同域不同端口**范围内生效。

## 五、构建与启动

在仓库根目录：

```bash
docker compose up -d --build
```

首次会做几件事：
1. 拉取 `postgres:16-alpine`；
2. 用 `docker/Dockerfile.app` 为**每个应用**构建镜像（七个应用共用一份 Dockerfile，
   靠 `--build-arg APP=<name>` 区分）；
3. `migrator` 跑 `prisma migrate deploy` + `npm run seed`（幂等），跑完退出；
4. 各应用等 `migrator` 成功后启动。

看进度与日志：

```bash
docker compose ps
docker compose logs -f migrator      # 迁移/种子结果
docker compose logs -f portal        # 门户
```

全部就绪后即可访问：经 Lucky 子域名走 `http(s)://nav.<你的域名>`，
或直连 `http://<NAS_IP>:3210`。用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录，
**第一件事就是改密码**。

> **内存提示**：compose 默认并行构建。飞牛若内存较小（≤8G），七个 Next 应用
> 一起构建可能 OOM。改成串行构建：
> ```bash
> COMPOSE_PARALLEL_LIMIT=1 docker compose build
> docker compose up -d
> ```

## 六、日常维护

```bash
docker compose ps                     # 状态
docker compose logs -f <服务名>       # 看某个服务日志，如 bill / worker
docker compose restart <服务名>       # 重启单个服务
docker compose down                   # 停止并删除容器（数据库数据落在 PG_DATA_DIR 目录，不会丢）
```

### 更新代码后

```bash
git pull
docker compose up -d --build          # 只重建有变化的服务（分层缓存会加速）
```

只重建某一个：

```bash
docker compose up -d --build bill
```

### 数据库备份

数据落在 `PG_DATA_DIR` 指向的宿主机目录（默认仓库下 `./pgdata`）。两种备份方式：

```bash
# 方式一：导出 SQL（推荐，跨版本可恢复）
docker compose exec -T postgres pg_dump -U nas nas_platform \
  | gzip > /vol1/1000/backups/nas-$(date +%F).sql.gz
```

也可以直接把 `PG_DATA_DIR` 整个目录纳入你的 NAS 备份策略（**先 `docker compose stop postgres` 再拷**，避免拷到写入中的文件）。

恢复：

```bash
gunzip -c /vol1/1000/backups/nas-2026-10-19.sql.gz \
  | docker compose exec -T postgres psql -U nas -d nas_platform
```

照片是直接挂在 `/vol1/1000/photos` 的普通文件，跟着你的相册备份策略走即可。

## 七、把现有数据迁进来

新库首次启动是空的（只有种子数据：平台注册表 + 初始管理员）。按旧数据来源选一种。

### A. 从本地开发 PostgreSQL 迁移（推荐路径）

这是把本地开发库（`localhost:5433`）的整份数据搬到 NAS 新库，最省事：

```bash
# 1) 本机导出（连接串用你本地 .env 里的 DATABASE_URL）
pg_dump "postgresql://nas:nas@localhost:5433/nas_platform" \
  | gzip > nas-migrate.sql.gz

# 2) 把 nas-migrate.sql.gz 传到 NAS（scp / 飞牛文件管理均可）

# 3) 在 NAS 的仓库目录里灌进新库
gunzip -c nas-migrate.sql.gz \
  | docker compose exec -T postgres psql -U nas -d nas_platform
```

> 自带 `pg_dump` 版本要 ≥ 目标库（PG16）。若本机是更老的 pg_dump，用与 NAS 同版本的
> 容器导出：`docker run --rm -i postgres:16-alpine pg_dump "<连接串>"`。

### B. 从旧的账单 SQLite（cash-platform）迁移

仓库自带迁移脚本，**顺序固定**：`migrate-users` → `migrate-bills` → `verify-bills`。

前置：
- 旧库文件 `ledger.db`（`backups/` 里有生产快照，如 `ledger-prod-20261014-171322.db`）。
- 需要 **`sqlite3` 命令行**（脚本靠它读 SQLite）。macOS 自带；飞牛上 `apt install sqlite3`。

在**装了 Node 的电脑**上跑，`DATABASE_URL` 指向 NAS 的新库：

```bash
export DATABASE_URL="postgresql://nas:<PG_PASSWORD>@<NAS_IP>:5432/nas_platform"
export MIGRATE_SOURCE=/绝对路径/ledger.db     # 也可用 --source <path> 指定

npm run db:generate
npx tsx packages/db/scripts/migrate-users.ts --dry-run   # 先看差异，不写库
npx tsx packages/db/scripts/migrate-users.ts             # 正式写
npx tsx packages/db/scripts/migrate-bills.ts --dry-run
npx tsx packages/db/scripts/migrate-bills.ts
npx tsx packages/db/scripts/verify-bills.ts              # 对账
```

> 要从外部连新库，需要先把 postgres 端口临时放开：在 `docker-compose.yml` 的
> `postgres` 下临时加 `ports: ["5432:5432"]`，迁完删掉。

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 门户能登录，跳转其它应用又变回登录页 | `AUTH_COOKIE_DOMAIN` 或子域名解析没配好；确认 `*.root` 解析到 NAS、`AUTH_COOKIE_SECURE=false` |
| 打开站点是 502 | 对应应用还没起来，`docker compose logs <服务名>` 看报错 |
| `migrator` 退出码非 0 | 看 `docker compose logs migrator`；多为 `DATABASE_URL`/`PG_PASSWORD` 不对 |
| 端口被占用 | 改 `.env` / compose 里对应应用的端口映射（`321x`） |
| 上传图片失败 | 目录权限问题，见第三节第 3 步；或配置了图床 `IMAGE_HOST_URL` 但 token 不对 |
| 浏览器提示不安全 | 内网 http 属正常；要 https 见下方 |
| 构建很慢/卡死 | 见第五节的串行构建提示 |

### 启用 HTTPS

在 Lucky（或飞牛自带反代、Caddy）上终止 TLS，然后把 `.env` 改成：

```
NAS_PUBLIC_PROTO=https
NAS_PUBLIC_PORT=        # 443 留空
AUTH_COOKIE_SECURE=true
```

## 九、外网访问（可选）

`docker-compose.yml` 末尾预留了 Tailscale。取消注释并在 `.env` 填 `TS_AUTHKEY`，
配合 MagicDNS + split DNS 即可在手机/外网访问，**无需把端口暴露到公网**。

> 切记：不要把这些端口映射到公网路由器上。
