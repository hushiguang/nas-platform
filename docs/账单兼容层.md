# 账单旧 API 兼容层（`/legacy/api/*`）

> 目的：让安卓端「轻记」（Capacitor 壳 + 无障碍自动记账）在账单并入 nav-platform 后**继续可用**，
> 且**不需要重新打包 APK**。

## 一、为什么挂在 `/legacy` 前缀下

老的账单服务端有 70 个 `/api/*` 路由，其中包含：

```
POST /api/auth/login
POST /api/auth/register
GET  /api/auth/config
```

而 nav-platform 的 Auth.js 占用了 `/api/auth/[...nextauth]` —— 这是个 **catch-all**，
会把 `/api/auth/login` 一并吞掉当成 Auth.js 自己的动作。所以原样镜像 `/api/*` 是行不通的。

解法：整层挪到 `/legacy/api/*`。

**安卓端只要在设置页把服务器地址改成 `http://<nas>:3000/legacy` 即可。**
客户端里所有地址（**连图片、导出、模板下载也在内**）都经过 `apiUrl()` 拼接：

```ts
export function apiUrl(path: string): string {
  const base = getApiBase();          // ← 设置页填的，存在 localStorage / Capacitor Preferences
  if (!base) return path;
  return `${base}${path.startsWith('/') ? '' : '/'}${path}`;
}
```

所以前缀不会漏路径，也不用改任何客户端代码。

## 二、架构：适配器与业务逻辑分离

| 文件 | 职责 |
|---|---|
| `src/modules/bill/legacy.ts` | **适配器**：路由分发、双通道鉴权、响应外壳。只用 Web 标准 `Request`/`Response`，**不依赖 Next** |
| `src/app/legacy/api/[...path]/route.ts` | **接线**：把 Next 的 `params` 转给适配器，仅 30 行 |
| `src/modules/bill/service/*` | **业务逻辑**：校验、SQL、规则一律在这里，适配器不写业务 |

适配器不引 `next/server` 有两个好处：

1. **可测**：脚本能直接构造 `Request` 调用 `handleLegacyRequest()`，不需要起 Next 服务（见 `scripts/smoke-legacy.ts`）。
2. **边界干净**：模块层不把 framework 类型泄漏出去。

## 三、响应约定（必须与旧服务端一致）

```
成功：{ ... }            HTTP 200
失败：{ "message": "…" }  HTTP 4xx / 5xx
```

状态码沿用旧语义：`400` 参数错、`401` 未登录、`403` 无权限、`404` 不存在、
`409` 用户名冲突、`501` **接口尚未迁移**（明确报错，不静默返回空数据）。

## 六、已知坑（都已在代码里处理）

1. **`.env` 的值带引号**（`AUTH_SECRET="dev-xxx"`）。
   Prisma Client 会自动加载 `.env` 并**去掉引号**，但手写解析会拿到带引号的原始值。
   冒烟脚本曾因此算出的签名密钥与模块层不同，导致 Bearer 全部被判未登录。
   → **不要自己解析 `.env`**，一律读 `process.env`。

2. **`auth()` 脱离请求上下文会抛错**。
   `actorFromSession()` 已包 try/catch 返回 `null`，这样脚本 / worker / 定时任务里调用时按「未登录」处理，而不是 500。

3. **密钥未配置时不能静默降级成 401**。
   `verifyToken()` 已把 `secretKey()` 提到 try 之外 —— 忘配 `AUTH_SECRET` 应当直接报 500 并说明原因，否则线上只会看到一片 401，查不出所以然。

4. **时区**：`occurredAt` 存 UTC 墙钟，所有按本地日期的分组/区间都要 `+ INTERVAL '8 hours'`。
   `service/report.ts` 里统一用 `LOCAL_TS` / `LOCAL_DAY` 两个片段，不要另写。
